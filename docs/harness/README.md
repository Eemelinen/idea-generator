# The Ideaforge harness

Ideaforge is built with the shared agent harness from
[Eemelinen/harness](https://github.com/Eemelinen/harness). It lets a coding agent build this
repository one feature at a time without drifting, and lets a driver run those sessions
unattended, one PR per feature. This page covers what is specific to Ideaforge. How the harness
works in general — the parts, one feature end to end, every safeguard, operating and reading the
loop — is in the harness docs:
[how it works](https://github.com/Eemelinen/harness/blob/main/docs/how-it-works.md),
[configuration](https://github.com/Eemelinen/harness/blob/main/docs/config.md),
[why each part exists](https://github.com/Eemelinen/harness/blob/main/docs/why.md).
The decisions behind it are D-001–D-007 in [../DECISIONS.md](../DECISIONS.md).

The harness is **development tooling**. It builds Ideaforge; it never runs the pipeline. A
pipeline session follows CLAUDE.md → Pipeline sessions instead of the clock-in loop.

Both pins name the same tag. `pnpm harness:doctor` (also run by `./init.sh`) fails when they
differ. To update: install the new tag
(`pnpm add -D "@eemelinen/harness@github:Eemelinen/harness#vX.Y.Z"`), set the marketplace `ref`
in `.claude/settings.json`, run `pnpm harness:doctor` and `pnpm check`, and commit as
`chore(harness): update to vX.Y.Z`. A change to the harness itself is made in the harness
repository, never here.

## Ideaforge specifics

- **One layer.**
  - L1 is `pnpm check`: Prettier, `pnpm harness:check` and the full `uv run pytest`.
  - Focused steps are `uv run pytest …`; the loop log reports them as milestones.
  - There is no L2/L3 and no services (`services: null`).
  - Steps that need the network, a real Claude run or a decision by the user are `manual:`.
- **Two guards.**
  - The harness guard (plugin) blocks bare `python`/`pytest`/`pip` and `pip install` (only
    where a command starts, so a heredoc or commit message does not trigger it).
  - It denies edits to `.claude/agents/*` (generated by `scripts/gen_agents.py`), `uv.lock` and
    `.env*`, and asks before edits to `config/models.yaml`.
  - The pipeline guard `ideaforge.guard` runs next to it. It treats `HARNESS_LOOP=1` as a
    development session (D-005) and lets the `harness:evaluator` agent run only the read-only
    harness checks, `pnpm test:py` and `grep`/`head`/`tail`/`wc`. Text inside quotes is not
    read as a redirect or a pipe.
- **Clean-state checks beyond the core.**
  - no skip/only/xfail added under `tests/`
  - no `fail_under` coverage threshold removed from `pyproject.toml`
  - no debugger call added under `src/` or `scripts/`
- **Models.** `harness.config.json` must use the `harness_generator` / `harness_evaluator` roles
  of `config/models.yaml` (`tests/test_harness_config.py`, D-004). The evaluator agent itself
  comes from the plugin and is no longer generated.

## Operating the loop here

**Prerequisites (once):**

- `uv`, `claude` and `gh` on `PATH`, with `gh` logged in.
- `main` clean and in sync with `origin/main`.
- On Windows, run the driver from Git Bash.
- Run `claude` in the repository once and accept the trust dialog and the plugin marketplace.

**Merging.** `merge: "auto"`: the loop opens a PR per feature and arms
`gh pr merge --auto --squash`, and GitHub merges it once the required check `L1 (pnpm check)`
passes (branch protection on `main`, no review requirement). A red check stops the loop; push a
fix to the branch and the PR still merges.

**Commands.** Start with `pnpm harness:loop --dry-run`, then `pnpm harness:loop --once`.
`pnpm harness:report` shows past runs.

**Caps.** 200 turns / 15 USD / 60 minutes per generator session, and 60 turns / 4 USD for the
evaluator.
